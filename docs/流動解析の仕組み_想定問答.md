# 流動解析ツールの仕組み（想定問答）

本資料は、流動解析ツールについて寄せられる質問に Q&A 形式で答えるものです。ツールの妥当性から、商用CAEとの違い、プログラムの作り、今後の展望までを扱います。

## ツールの妥当性と設計

### Q. これは素人が独自に作ったツールではないのですか？

計算の土台となる物理モデルは、独自の理論ではなく確立された標準を用いています。流路の流動性を表す Hele-Shaw 近似は Hieber-Shen（1980）に始まり、商用CAE Moldflow の中立面解析の数学的土台でもあります。粘度の Cross-WLF モデルは Moldflow / Moldex3D も採用する業界標準です。独自に実装したのは、これらの標準理論を「薄肉の導光板」という前提が成り立つ範囲に当てはめる部分（形状の離散化・方程式の組み立て・可視化）に限られます。土台が公知である以上、モデルの妥当性は第三者が独立に判断でき、コードも MIT ライセンスで公開しています。

### Q. 解析結果の妥当性は、どの程度のレベルですか？

「どの問いに使うか」で妥当性は大きく変わります。3つの階層に分けて説明します。

1. **計算（解法）の正しさ** — 答えを手計算で出せる単純なケースと突き合わせ、誤差2%以内で一致することを確認しています。メッシュを細かくするほど誤差が減ることも確認済みで、「方程式を正しく解けている」ことは検証されています。
2. **物理モデルの妥当性** — 土台のモデル（Hele-Shaw・Cross-WLF）自体は、薄肉流動で実験と数%〜1割程度で一致する確立された理論です。ただし本ツールはその上に割り切りを重ねているため、形が単純なほど妥当、複雑なほどズレます。
3. **絶対値の予測精度** — 充填時間や圧力の絶対値は保証しません。参考値とお考えください。

総じて、**設計案同士の相対比較には十分使える妥当性**を持ちますが、**絶対値を当てる用途には向きません**。なお、実機や商用CAEとの定量的な突き合わせ（バリデーション）は今後の課題です。

### Q. テストや検証は「自分で作って自分で採点している」だけではないですか？

品質を支える仕組みは2種類あり、性質が違います。一つは約180個の自動テストとCI（コード変更のたびに自動実行）で、これは「コードが意図通り動くこと」を保証します。ただし、確かに私たち自身が立てた基準での自己採点であり、「現実を当てること」までは保証しません。もう一つは解析解との照合で、こちらは採点者が私たちの外＝数学です。単純な形状なら厳密な答えが数式で導けるので、ソルバーの出力をその厳密解と突き合わせ、最大2%以内で一致することを確認しています。ただしこの照合の対象は「充填の進み方の形」であって、充填時間や圧力の絶対値は対象外です。この線引きはテストコード自身に明記してあり、隠していません。つまり、検証した範囲と保証する範囲は一致しています。

### Q. 物理モデルの選択は、どのように決めましたか？

対象が極薄プレート（導光板）であることが出発点です。次の3つの基準で絞り込みました。

- **対象形状に合うか** — 導光板は薄く平面的に広い形状で、Hele-Shaw 近似の前提（厚みが他の寸法よりずっと小さい薄肉）に合致します。
- **業界で確立されているか** — 粘度が温度と剪断で変わる性質は外せず、それを表す業界標準の Cross-WLF を採用しました。商用CAEでも使われ、材料データも入手しやすい点も理由です。
- **目的（速さ）に合うか** — 充填の順番を解くのに、重い時間発展計算を避け、軽い一発計算を選びました。

思いつきではなく、対象・標準性・目的の3点で選定した結果です。

## 商用CAEとの関係

### Q. 商用CAEがどんな計算をしているか、把握していますか？

把握しています。Moldflow と Moldex3D の公式資料で確認しました。

商用CAEは射出成形の全段階（充填→保圧→冷却→反り）を、多数の物理モデルを連成して解きます。主なものだけでも、流動の基礎方程式（質量・運動量・エネルギー保存）、Cross-WLF 粘度、Tait pvT 状態方程式（密度の圧力・温度依存）、樹脂先端の自由表面追跡、金型冷却の熱伝導連成、結晶化、繊維配向、残留応力・反り（粘弾性）まで含みます。

本ツールが扱うのは**充填段階の流動だけ**、しかも Hele-Shaw 近似に簡略化した版です。保圧・冷却・結晶化・繊維配向・反りは一切扱いません。物理モデルとして共有しているのは Hele-Shaw と Cross-WLF の2つだけで、商用CAEが連成する物理の大半は本ツールにありません。

解析の規模も、Moldflow は中立面・Dual Domain・フル3Dのメッシュを使い分け、Moldex3D はフル3Dで厚み方向まで解きますが、本ツールは2次元の薄肉近似に固定です。

### Q. 把握しているなら、なぜ同じ計算をしないのですか？

意図的な役割分担です。理由は3つあります。

1. **目的が違う** — 商用CAEは最終検証・絶対値予測、本ツールは予備検討・相対比較。狙う精度の階層が別です。
2. **開発コスト** — 完全な時間発展3D連成は専門知識と膨大な工数を要し、商用CAEは数十年・大人数で作り込まれています。
3. **計算資源** — フル3D連成は1ケース数時間かかり、「多数案を高速に試す」という目的と矛盾します。

率直に言えば、同じことを目指しても個人開発では商用CAEには届きません。だからこそ競合を狙わず、その前段に特化しました。速く割り切る一点に振り切ったことが、本ツールの価値です。

### Q. 一発で解かず、複数回に分けて解けば精度は上がりますか？

上がります。ただし「分け方」によります。まず大前提として、**同じ一次方程式をただ複数回解いても精度は上がりません**（一発で厳密解が出るため）。精度が上がるのは、次の2つの場合だけです。

1. **粘度を反復更新する** — 今は粘度を代表値で1回だけ固定しています。「解く→実際の流速が出る→その流速に合った粘度を計算し直す→再度解く」と繰り返せば、粘度が実態に近づき精度が上がります。商用CAEはこれを行います。
2. **時間を刻んで樹脂先端を進める** — 到達地図を1回解く代わりに、時間を細かく刻んで先端を前進させ、各ステップで物理量を解き直せば、流れの履歴（合流・分岐・冷えの進行）を正しく追え、複雑形状での精度が上がります。これが商用CAEのフロント追跡解析です。

ただし、どちらも精度と引き換えに計算が重くなります。これらの取り込みは本ツールが意図的に省いた部分であり、速さという取り柄を手放すことを意味します。

## プログラムとしての作り

### Q. なぜ Python を選んだのですか？

数値計算の生態系が充実しているためです。numpy・scipy・matplotlib という定番ライブラリが無料で揃い、これらの中身は C や Fortran（高速な言語）で書かれているため、重い計算はそこに任せて高速に処理できます。「書きやすさ」と「計算の速さ」を両立できる点が決め手です。加えて Streamlit で操作画面まで作れ、無料で公開できます。速く作って速く試す、当たりをつける道具に最適な選択です。

### Q. Python 以外でも同じことはできますか？

できます。本ツールが行う計算（疎行列の連立一次方程式を解く）は、言語に依存しない標準的な数値計算です。MATLAB（科学計算の老舗、有料）、Julia（高速）、C++ / Fortran（最速・商用CAEの中核）などでも実装できます。それでも Python を選んだのは、実行速度より開発の速さ・無料・画面の作りやすさを優先したためです。性能を極限まで追うなら他言語ですが、それは商用CAEの土俵になります。

### Q. 「配列演算」「疎行列ソルバー」とは何ですか？

- **配列演算** — 数字をマス目状に並べた表の全マスに、一斉に計算をかける仕組みです。1マスずつ順に処理せず表ごと一括で扱うため高速です。これを担うのが numpy です。
- **疎行列** — 「疎」はスカスカという意味です。連立方程式を表（行列）にすると、各マスは隣としか関係しないため、巨大な表のほとんどがゼロになります。そのゼロでない場所だけを記憶する節約形式が疎行列です。
- **疎行列ソルバー** — このスカスカな巨大連立方程式を効率よく解くプログラムです（scipy の `spsolve`）。何万マスあっても、ほとんどがゼロという性質を突いて現実的な時間で解きます。

### Q. Streamlit とは何ですか？

Python のプログラムを、ブラウザで動く操作画面に手軽に変える道具です。スライダー・ボタン・グラフ表示が簡単に作れます。本ツールでパラメータを操作し、結果のグラフを表示している画面が、これにあたります。計算の中身がエンジンなら、Streamlit は運転席の計器とハンドルにあたります。

### Q. 「連立一次方程式」の「一次」を強調する意味は？

「一次」とは未知数が1乗だけ（二乗や未知数同士の積が出てこない）という意味で、これが本ツールの速さの核心です。一次（線形）の方程式は「行列 × 未知数 = 既知の値」というきれいな形に収まり、一発で確実に解ける解法が確立しています。もし非線形（二乗が混じる等）なら一発では解けず、推測と修正を繰り返す反復計算が必要になります。本ツールは粘度を最初に固定値として決めることで方程式を一次に保ち、一発計算を可能にしています。

### Q. 物理モデルをプログラムに落とすとき、何に気を付けますか？

- **単位系の統一** — mm と m、Pa と MPa の混在は答えを壊します。
- **境界条件を物理的に正しく** — ゲートは到達時間ゼロ、外壁は樹脂が漏れない、という条件を正しく設定します。
- **数値の安定性** — 薄肉では $h^3$ が極端に小さくなるため、ゼロ割りや発散を防ぐ下限値を設けます。
- **検証できる作り** — 答えが手計算で出る単純ケースを用意し、バグに気づけるようにします。
- **近似の前提を守る** — Hele-Shaw は薄肉前提のため、厚い形状には使いません。

最も重要なのは、「正しく解けていること」と「正しい問題を解いていること」を分けて検証することです。解法のバグとモデルの限界は別物で、混同すると原因の切り分けができなくなります。

## 今後の展望

### Q. より複雑な形状の流動解析アプリは作れますか？どんなアプローチになりますか？

「複雑」の中身で答えが分かれます。

- **平面的に複雑な形状（外形が入り組む・肉厚分布が複雑）** — 今の Hele-Shaw 系の延長で対応できます。メッシュを細かくし、外形と肉厚を持たせれば、薄肉前提が成り立つ範囲で扱えます。
- **真の3D形状（リブ・ボス・曲面・厚み方向の流れが効く）** — Hele-Shaw（薄肉前提）が成り立たず、別の解法が必要です。段階としては、中立面メッシュ＋時間発展（Moldflow midplane 相当、難度は中〜高）、あるいは有限体積/有限要素で3D Navier-Stokes を解き樹脂先端を追跡するフル3D（商用CAEの領域、難度は非常に高い）が考えられます。

現実的には、3D をゼロから書くより、OpenFOAM や FEniCS といった既存のオープンソース3Dソルバーを土台に、射出成形特有の物理（Cross-WLF・固化・フロント追跡）を載せる方が筋が良いです。また本ツールの設計方針として、既存の解法に無理に機能を足さず、新しい解法を別に並べて立てる形を取ります。

結論として、**平面的な複雑形状は今の延長で可能、真の3Dは技術的に可能だが商用CAEに匹敵させるのは非現実的**、既存3Dソルバーの活用で実用レベルのものは作れる、という見立てです。
