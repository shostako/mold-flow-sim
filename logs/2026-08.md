### 充填アニメーションをシーク可能なHTML5プレイヤーに置換（PR #47 / v0.15.0）

自動再生されるだけの GIF 表示を、ドラッグで任意位置に止められるプレイヤーに差し替えた。

- `core/fill_player.py`（新規）— `build_fill_player_html()` / `fill_player_height_px()`。
  フレーム PNG を data URI で埋め込んだ自己完結 HTML。再生・一時停止、ドラッグシーク、コマ送り、
  速度 0.25〜2x、ループ、キーボード（Space / ←→）。**操作は全部ブラウザ内で完結しサーバに戻らない**。
- `visualizer.fill_frame_times()` / `fill_frame_fractions()`（新規）— GIF・PNG連番・プレイヤーが
  共有するフレーム時刻の単一ソース。
- GIF は従来どおり ZIP に同梱（ダウンロード用途は不変）。UI 表示だけ差し替え。

**追加コストがゼロだった理由**: `export_frames` が以前から ZIP 同梱用に全フレーム PNG を書き出していた。
既定60フレームで PNG 合計 1.26MB、base64 化して約1.7MB。

**重複の解消**: フレーム時刻の `linspace` が `render_fill_animation` と `export_frames` の2箇所に重複していた。
プレイヤーで3箇所目を作れば必ずズレるので、先に集約してから使った。3者のフレーム k が同じ瞬間である
ことをテストで固定（`tests/test_fill_player.py` 11件、全体 262 passed / 1 skipped）。

**検証で潰したUIバグ2件**（どちらもテストは通ったまますり抜けるやつ）:
1. **豆腐グリフ** — コマ送り/ループに U+23EE / U+23ED / U+1F501 を使い、絵文字フォントのない環境で□になった。
   Geometric Shapes（◀▶）＋日本語ラベルに置換。ローカル起動の目視で発見。
2. **iframe幅による操作列の切れ（Codex P2）** — `components.html` の高さは固定なのに iframe 幅は列幅に追従する。
   列が画像ネイティブ幅(700px)を超えると 7:5 の画像が縦に伸びて固定高さを超え、`scrolling=False` と相まって
   **操作列が画面外に出てプレイヤーが操作不能**（幅1100pxで889px必要／604px確保）。
   → `#stage` をネイティブ幅で頭打ち＋高さを PNG 実寸から導出（`app.py` のハードコード `int(700*(5/7))` を削除）。
   幅1100pxで操作列下端570px＜604px を実測確認。回帰テスト3件追加。

**教訓**: 1 はテスト緑・2 はローカル目視も通過した。**「画面に出て動いているのを見た」は「幅を振って確かめた」ではない**。
レスポンシブな埋め込みは寸法を変えて確認する。

### 圧縮成形のスコープ確認（コード変更なし）

「圧縮ストロークが効くのは製品部分だけか」の確認。`solver._open_thickness_field()` は
`compression_mask & mask` にだけ stroke を加算し、`profile_gate.py` は `compression_mask = in_plate & mask`。
実測でもプレートセルは全て +stroke、ゲートブロックのセルは Δh=0.000（1セルも動かない）。
Film gate / Direct gate / Film gate2 も同じ流儀。**例外は `build_demo_geometry` と `geometry_from_image` で、
`compression_mask=None` のため全セルが膨張する（旧挙動）**——画像から形状を作った場合はランナごと膨らむ。

副作用として、`effective_factor` は**分子が圧縮対象面積、分母が全キャビティ体積（ゲート部込み）**なので、
ランナが太いほど圧縮の効きが薄まる（意図的な設計）。ランナが製品と同体積規模だと効きが3割方削られる。
